# Emulator test, 2026-11-22

A hands-on pass over the plan's phases and the user guide, done as a listener would, on the
Android emulator (Pixel-class phone, 1080 × 2424, 420 dpi, Android 17, API 37) with the Google Play
debug build (0.1.0 (1)) and, for one check, the release build signed with a debug key. Driven with
`adb` (`uiautomator dump`, `input`). Media volume was 0 while music played.

Servers:

| Server | What it is |
|---|---|
| **canary** | own.audio at `api-canary.own.audio` (1.0.7), a member account of a test family (76 songs, a concert, two shared smart playlists, no songs of its own) |
| **own.audio test** | a second own.audio server (a small library) |
| **Navidrome** | Navidrome 0.64.2 (OpenSubsonic), 1557 songs |
| **Jellyfin** | a Jellyfin server, about 10,000 songs in one music library |
| **Ampache** | an Ampache server on a home network |
| **demo** | the public demo library (Try the Demo Library) |

Everything changed on the servers was put back afterwards (see Cleanup).

## Not testable here

- A big first sync on canary: the member account holds 76 songs (the 600k-song scale test in the
  plan was run on generated data).
- Android Auto on a head unit (the browse tree is covered by `AutoLibraryTest`).
- Gapless by ear or by recording (transitions were checked by position only).
- Saver and Data Saver on real mobile data (the emulator's network is unmetered; covered by
  `PlaybackSettingsTest`).
- Keep at Most eviction (the smallest limit is 1 GB).
- The streamed copy swapped for a fresh download (the plan lists it as still open).
- Sharing, covers and Edit Songs of own songs, and Identify runs: the account has no songs of its
  own (the screens were checked hidden; the concert editor's swipe is covered by `SwipeRowsTest`).
- Sign in with Google, two-factor, Quick Connect approval, the widget on the home screen.
